# ReuseMe - License and Copyright Management

ReuseMe provides a [Pre-commit hook](#pre-commit), [Command Line Interface](#local-development-command-line-interface) and [integration with GitHub Actions](#cicd-validation-github-actions) for managing software licensing and copyright attributions, including support for:

* [Validation](./docs/specifications.md) of your files against the [Reuse specification]
<img src="./docs/images/cli_example.svg">
* Generation of an SPDX 2.3 compatible Software Bill of Materials (SBOM)

  ```json
  {
    "SPDXID": "SPDXRef-DOCUMENT",
    "spdxVersion": "SPDX-2.3",
    "name": "reuse-me",
    "documentNamespace": "http://spdx.org/spdxdocs/spdx-v2.3-HASH",
    "dataLicense": "CC0-1.0",
    "creationInfo": {
      "comment": "Generated by ReuseMe",
      "created": "2023-06-15T12:45:54.800Z",
      "creators": [
        ...
      ]
      ...
    }
    ...
  }
  ```

## Pre-commit hook

You can add ReuseMe as a [pre-commit](https://pre-commit.com) by:

1. [Installing pre-commit](https://pre-commit.com/#install)
2. Including ReuseMe in your `.pre-commit.config.yaml` file, e.g.:

```yaml
repos:
- repo: https://github.com/dev-build-deploy/reuse-me
  rev: v1.3.0
  hooks:
  - id: reuse-me
```
3. Installing the hooks
```
$ pre-commit install
```

The hook validates the staged files pre-commit passes to it; when the commit changes `.reuse/dep5`, a `REUSE.toml` or a
file in `LICENSES/`, it validates every tracked file.

## CICD validation (GitHub Actions)

The basic workflow can be set up as such:

```yaml
name: Copyright & Licenses
on:
  pull_request:

jobs:
  reuse-me:
    name: REUSE compliance
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dev-build-deploy/reuse-me@v1
```

_You can find more details in the [dedicated documentation](./docs/github-action.md)_

## Local Development (Command Line Interface)

Performing local validation is as simple as running the `reuse-me` CLI tool, which validates every file `git` tracks
(or only the files you name);

```sh
$ reuse-me
$ reuse-me src/new-file.ts
```

_You can find more details in the [dedicated documentation](./docs/cli.md)_

## Claude Code plugin

The `reuse-me` plugin keeps [Claude Code](https://claude.com/claude-code) from writing a file CI would reject. It favours in-file headers over `.reuse/dep5`: a header travels with the file, so its copyright and licence stay traceable when the file is copied out of the repository or leaks, while a dep5 entry stays behind.

When Claude creates a new file:

- a file with a comment syntax (code, scripts, shaders, YAML, TOML, CSS, Markdown and HTML) gets the SPDX header, in its comment syntax and after a shebang, XML declaration, doctype or front matter, with the copyright and licence your rules give for that path; **also when `.reuse/dep5` or `REUSE.toml` already covers the path**. If a dep5 stanza covers it too, the hook warns: REUSE adds both up (two licences in the SBOM), so drop that path from dep5;
- a file without one (pictures, models, fonts, audio, JSON, binaries) gets no header: written as it is when `.reuse/dep5` or `REUSE.toml` covers it, otherwise denied with the exact dep5 stanza to add (`"dep5": "append"` lets the hook append it; `"sidecars": true` writes a `.license` file instead);
- existing files are left as they are, and a path without a rule is denied with `no licence rule for <path>: add one to .reuse-me.json`.

A `reuse-compliance` skill explains headers, annotations, the `LICENSES/` folder and what the ReuseMe check looks for.

```
/plugin marketplace add dev-build-deploy/claude-plugins
/plugin install reuse-me@dev-build-deploy
```

Or enable it for everyone working in a repository, in its `.claude/settings.json`:

```json
{
  "extraKnownMarketplaces": {
    "dev-build-deploy": { "source": { "source": "github", "repo": "dev-build-deploy/claude-plugins" } }
  },
  "enabledPlugins": { "reuse-me@dev-build-deploy": true }
}
```

Or straight from this repository, without the marketplace: `claude --plugin-dir ./claude-plugin`.

The rules live in `.reuse-me.json` in your repository root (first matching rule wins):

```json
{
  "rules": [
    { "paths": ["engine/**"], "holder": "Kevin de Jong <monkaii@hotmail.com>", "year": 2024, "license": "MPL-2.0" },
    { "paths": ["games/**"],  "holder": "Kevin de Jong <monkaii@hotmail.com>", "license": "LicenseRef-Proprietary" }
  ],
  "defaults": { "holder": "Kevin de Jong <monkaii@hotmail.com>" },
  "exclude": ["vendor/**"],
  "dep5": "deny"
}
```

`holder` is a string or a list (the year is prefixed unless given), `year` defaults to the current year, `defaults` apply when no rule matches (without a default licence the only file in `LICENSES/` is used), `exclude` paths are never touched, `dep5` is `"deny"` (the default; keep it when your dep5 is generated by a script) or `"append"`, and `sidecars: true` opts in to `.license` files. The plugin is glue: ReuseMe stays the deterministic check in CI. Its tests run with `claude plugin test claude-plugin`.
